# TGU — Telegram Unlocker

**RNMDTEAM · Public Android source · TGU 0.9.4 / RNMD ID**

TGU is an Android-first Telegram connectivity diagnostic tool and local MTProto proxy engine. Telegram connects to TGU on loopback at `127.0.0.1:1443`; TGU can route outgoing Telegram sessions through a selected classic MTProto or SOCKS5 upstream.

> **Scope:** TGU does not create a system-wide VPN and does not reroute other apps. Its foreground service hosts a loopback-only MTProto endpoint for Telegram. RNMD ID can use Telegram OpenID Connect only to authenticate the user's RNMDTEAM account; TGU does not log in to Telegram Messenger, read chats or messages, or request a phone number.

## MVP 0.8.0

- Figma-aligned dark Android interface with Home, Catalog, Diagnostics, Account and Settings screens; live engine and upstream values replace design-time examples.
- Settings page containing diagnostics, Proxy Manager, Freedom Checker catalog and failover settings.
- TGU Proxy Directory active-verified JSON catalog at `https://raw.githubusercontent.com/sergeyrenamed-coder/TGU-Proxy-Directory/main/data/proxies.json`, with Freedom Checker as fallback; no WebView is required.
- Directory records are filtered by server probe status, while TGU independently validates candidates from the phone's current network before use.
- Last successful catalog snapshot is cached locally. A failed refresh does not erase the previous catalog.
- Default catalog refresh interval: 5 minutes. Freedom Checker's own probes re-check entries approximately every four hours; polling its JSON more often does not make its probes run faster.
- Local upstream health check defaults to every 60 seconds.
- Automatic full-catalog device-side selection when TGU starts without an upstream; tests every supported candidate, then re-tests the five fastest and applies the best stable route.
- Automatic failover after three consecutive failed checks using the same full-catalog probe; automatically managed routes are re-optimized every 30 minutes only when a replacement is materially faster.
- SOCKS5 candidate test performs SOCKS negotiation, CONNECT to `telegram.org:443`, TLS/SNI validation and an HTTP response check.
- Classic MTProto candidate test performs an obfuscated2 handshake and sends an unauthenticated `req_pq_multi` request; a valid `resPQ` response confirms the secret was accepted by a Telegram DC. No Telegram account credentials are used.
- WEB/FakeTLS entries are shown as unsupported by the current upstream transport and are not selected automatically.
- Changing upstream preserves Telegram's local endpoint `127.0.0.1:1443`; active Telegram sessions may reconnect when a failover occurs.
- Telegram proxy settings are handed off only by the Home screen action `Применить Proxy в Telegram`. Autoselection, profile management, tests and failover do not launch Telegram or send proxy links.
- The app UI does not seed sample endpoints or demo proxy cards; catalog results come from the live JSON snapshot/cache and saved profiles come from encrypted local storage.
- TGU uses RNMD ID, a shared RNMDTEAM account authenticated through Telegram Native Login, PKCE, a verified Android App Link and Supabase Auth. Telegram consent opens in the installed Telegram app; the external browser is not part of the login flow.
- Supabase access/refresh tokens and the Telegram Native Login PKCE verifier are encrypted locally with AES-GCM using Android Keystore; the Telegram Client Secret never ships in the APK. A narrow Supabase Edge Function relays the fixed Telegram cross-app/token requests, then Supabase Auth validates the Telegram ID token for the custom:telegram provider.
- The account screen shows the verified Telegram profile, registered devices, recent orders and TGU+ entitlement state. User data is protected by row-level security.
- Device registrations are bound to individual Supabase Auth sessions. Revoking another device deletes its server-side Auth session and RLS blocks that session from reading account data.
- Telegram login requests only the `openid` and `profile` scopes. TGU does not request phone number, messages, contacts or bot access. The App Link `https://app2482922030-login.tg.dev/tglogin` is generated by Telegram and handled by Android; the Supabase callback remains registered separately in BotFather Redirect URLs. One-time provider setup is documented in `docs/RNMD_ID_TELEGRAM_LOGIN.md`.
- Upstream proxy credentials remain encrypted on-device and are not uploaded to the account database. Cross-device proxy sync will use a separate end-to-end encrypted vault.
- Encrypted MTProto/SOCKS5 profile manager using AES-GCM and Android Keystore.
- Proxy credentials are excluded from diagnostic reports.
- No third-party analytics or usage telemetry endpoint.

## Proxy types

**Classic MTProto**
- Required fields: server, port and hexadecimal secret.
- TGU checks the TCP endpoint and MTProto secret format. The actual secret/protocol is confirmed only when Telegram traffic succeeds.
- WEB/FakeTLS secrets are not supported by the current upstream connector.

**SOCKS5**
- Required fields: server and port; username and password are optional.
- Health checks negotiate SOCKS5, request a tunnel to `telegram.org:443`, then perform TLS/SNI and an HTTP response check.
- When selected as an upstream, TGU opens a SOCKS5 CONNECT tunnel to the Telegram DC requested by the local client.

## Build

Requirements: Android Studio with Android SDK Platform 36, JDK 17, Android Gradle Plugin 8.11.1, Kotlin Gradle Plugin 2.2.21 and Gradle 8.13.

```powershell
.\\gradlew.bat :app:assembleDebug
```

APK output: `app\\build\\outputs\\apk\\debug\\app-debug.apk`. GitHub Actions builds a debug APK on pushes to `main`; artifacts are retained for 14 days.

## TGU Community Network

- Loads the community proxy catalog from the RNMDSTORE Netlify API first, then falls back to the canonical GitHub Raw catalog when the API is unavailable.
- Community health data is supplemental: each device continues to probe proxies locally, and community ranking is applied only when enough distinct reporters are available.
- Anonymous community feedback is opt-in and disabled by default. Enabling it allows the app to submit proxy probe outcomes; it does not submit Telegram messages, account credentials, or phone numbers.
- The API base URL is supplied to CI through the `TGU_COMMUNITY_API_BASE_URL` repository variable.
