# RNMD ID — Telegram Native Login

TGU uses RNMD ID as the shared account identity for RNMDTEAM services. Telegram is the identity provider. The Android app uses Telegram's native cross-app login flow, receives the Telegram ID token, then exchanges it with Supabase Auth for the RNMD ID session.

## Telegram application registration

The Android application is registered in @BotFather under Bot Settings → Login Widget / Native Login.

| Setting | Value |
|---|---|
| Android package name | `com.rnmd.tgu` |
| Telegram Client ID | `9135700460` |
| Android App Link | `https://app2482922030-login.tg.dev/tglogin` |

The App Link is generated by Telegram. It is not a manually editable redirect URL in BotFather. The Android manifest declares it as a verified HTTPS App Link.

BotFather's **Redirect URLs** list must retain the Supabase OIDC callback:

```text
https://hscsswcevngohjdyetjo.supabase.co/auth/v1/callback
```

The Android Native Login App Link is separate from that Supabase callback.

The registered package name and SHA-256 signing fingerprint must match the APK. CI verifies that the APK uses the persistent TGU signing certificate before publishing it.

## Supabase custom OIDC provider

The existing Supabase provider is retained:

| Setting | Value |
|---|---|
| Project | `hscsswcevngohjdyetjo` |
| Provider identifier | `custom:telegram` |
| Issuer URL | `https://oauth.telegram.org` |
| Client ID | Telegram Client ID from BotFather |
| Scopes | `openid profile` |
| Email optional | Enabled |

The Telegram Client Secret, when required by provider configuration, stays in Supabase Auth. It is never included in the APK or this repository.

Supabase validates the ID token signature, issuer, and audience against the configured custom OIDC provider and issues the RNMD ID access/refresh session.

## Native login flow

1. TGU creates a cryptographically random PKCE verifier and its S256 challenge.
2. TGU calls the `telegram-native-login` Supabase Edge Function with the challenge.
3. The Edge Function requests Telegram's `/crossapp` endpoint and returns the native Telegram deep link.
4. Android opens that link. Telegram presents its native consent screen; no external browser login is launched.
5. Telegram returns an authorization code to `https://app2482922030-login.tg.dev/tglogin`, which Android routes to TGU through the verified App Link.
6. TGU sends the authorization code and its locally held PKCE verifier to the Edge Function. The Edge Function exchanges them at Telegram's `/token` endpoint and returns only the ID token.
7. TGU submits the ID token to Supabase Auth using the `custom:telegram` ID-token grant. Supabase validates it and returns the RNMD ID session.
8. The session is encrypted locally using AES-GCM with a non-exportable Android Keystore key.

The Edge Function has two fixed actions (`start` and `finish`). It accepts no arbitrary destination URLs, keeps the Telegram Client ID and redirect URI fixed, validates the PKCE challenge/verifier format, uses short upstream timeouts, and does not log or persist authorization codes, verifiers, ID tokens, or session tokens. The function is callable before a user is authenticated; it does not have access to database rows or privileged Supabase keys.

## Privacy and account behavior

- Only the `openid` and `profile` scopes are requested.
- TGU does not request a phone number, Telegram messages, contacts or bot access.
- The native consent screen is handled by the installed Telegram app.
- The Android browser is not used for Telegram authentication.
- RNMD ID profile creation, device registration/revocation, orders, and entitlement checks remain in Supabase.
- Supabase access/refresh tokens and the PKCE verifier are encrypted locally using Android Keystore.
- Proxy credentials remain local and encrypted. They are not synced to the account database.
- TGU Free continues to work without an RNMD ID account.

## First sign-in test

1. Install TGU 0.9.2.
2. Start TGU and open the Account tab.
3. Tap **Continue with Telegram**.
4. Telegram should open its native login/consent screen rather than an external browser.
5. Approve the login. Telegram should return to TGU.
6. Verify that the RNMD ID profile and current device appear.
7. Sign in on another device and verify that device revocation works as before.

If the device asks which app should handle the Telegram App Link, select TGU. If Telegram does not open, update the Telegram app and check that the App Link host and SHA-256 fingerprint registered in BotFather match this build.
